Project notes

Reviewing a ledger row by row takes time, and some exceptions need more attention than others. This prototype gives a reviewer a starting list with an explanation for every flag.

  • Duplicate invoice. Match vendor and invoice ID, ignoring capitalization and surrounding spaces. Flag every row in a matching group.
  • Missing approver. Flag a blank approver field for follow-up against the original approval records.
  • Above the limit. Flag amounts strictly greater than the chosen threshold.

Example. At the default $500 threshold, the sample produces seven flags across six transactions. Row 8 is missing an approver and is above the threshold. Row 11 is exactly $500 and stays clear. The two $215 Blue Finch entries with invoice INV-102 are flagged, while the separate $215 invoice INV-107 stays clear.

Design choice. The checks and memo use explicit rules in JavaScript so a reviewer can reproduce each result. A flag calls for checking supporting records. The prototype does not determine whether a payment is invalid or whether fraud occurred.

Built with AI assistance. Runs locally in a browser with no dependencies or model API.
